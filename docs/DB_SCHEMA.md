# MongoDB Database Schema

This document describes all MongoDB collections used by SkillANA, including fields, types, constraints, and relationships — based on the Mongoose models in `lib/models/schema.ts` and how each API route interacts with the database.

---

## Collections Overview

| Collection | Model | Purpose |
|---|---|---|
| `users` | `User` | Registered users, their profile, badges earned |
| `pendinusers` | `PendingUser` | Temporary pre-registration data waiting for OTP |
| `badges` | `Badge` | Available skill badges and their test questions |
| `badgecategories` | `BadgeCategory` | Category labels for grouping badges |
| `otps` | `Otp` | One-time passwords for email verification (TTL: 5 min) |

---

## Collection: `users`

Stores fully registered users. Created after OTP verification is complete.

```
users
├── _id               ObjectId        Auto-generated by MongoDB
├── firstName         String          Required
├── lastName          String          Required
├── email             String          Required, Unique
├── password          String          Optional (null for Google OAuth users, bcrypt hashed)
├── profileImg        String          Default: "/user.png"
├── aboutMe           String          Optional — short bio text
│
├── contact           Object
│   ├── phoneNumber   String          Default: ""
│   └── address       String          Default: ""
│
├── education         Object
│   ├── level         String          Default: "" (e.g. "Bachelor's")
│   ├── major         String          Default: ""
│   ├── university    String          Default: ""
│   ├── startDate     Date            Optional
│   └── endDate       Date            Optional
│
├── experience        Array<Object>   Can be empty
│   └── [...]
│       ├── _id       ObjectId        Auto-generated (subdocument)
│       ├── title     String
│       ├── startDate Date
│       ├── endDate   Date            Optional
│       └── description String        Optional
│
├── badges            Array<Object>   Badges earned by the user
│   └── [...]
│       ├── _id       ObjectId        Auto-generated (subdocument)
│       ├── badgeId   ObjectId        Ref → badges._id
│       ├── badgeName String
│       ├── imgUrl    String
│       └── earnedAt  Date            Default: Date.now
│
├── createdAt         Date            Auto (timestamps: true)
└── updatedAt         Date            Auto (timestamps: true)
```

### Notes
- `password` is absent for users who registered via Google OAuth.
- `badges` uses `$ne` check before pushing to prevent duplicate badge entries.
- `GET /api/users/[id]` and `GET /api/auth/register` exclude `password` from responses via `.select("-password")`.

### API routes that use this collection

| Method | Route | Operation |
|---|---|---|
| `POST` | `/api/auth/login` | `findOne({ email })` — validates password, returns JWT |
| `GET` | `/api/auth/register` | `findById(payload.id)` — fetch user from token |
| `PUT` | `/api/auth/register` | `findByIdAndUpdate(decoded.id, body)` — update profile |
| `POST` | `/api/auth/register` | `User.create(...)` — promote pending user to real user |
| `POST` | `/api/auth/google` | `findOne({ email })` / `User.create(...)` — find or create |
| `GET` | `/api/users/[id]` | `findById(id).select("-password")` |
| `PUT` | `/api/users/[id]` | `findByIdAndUpdate(id, body)` — JWT-protected |
| `POST` | `/api/users/[id]/badge` | `findOneAndUpdate(...)` with `$push` — award a badge |

## Collection: `pendinusers`

> **Mongoose model name:** `PendingUser` → MongoDB collection name: `pendinusers`

Temporarily holds user registration data until OTP is verified. Once verified and registered, the document is deleted.

```
pendinusers
├── _id         ObjectId    Auto-generated
├── firstName   String      Required
├── lastName    String      Required
├── email       String      Required
└── password    String      Required — bcrypt hashed (10 salt rounds)
```

### Notes
- Created by `POST /api/auth/register/pending-users` during the sign-up flow.
- Deleted by `POST /api/auth/register` after the real `User` document is created.
- No TTL is set — old pending users persist until the flow completes or is re-attempted.

### API routes that use this collection

| Method | Route | Operation |
|---|---|---|
| `POST` | `/api/auth/register/pending-users` | `findOne({ email })` check, then `PendingUser.create(...)` |
| `POST` | `/api/auth/register` | `findOne({ email })` to retrieve data, then `deleteOne({ email })` |

## Collection: `badges`

Stores all available skill badges, their category, test questions, and pass criteria.

```
badges
├── _id             ObjectId        Auto-generated
├── badgeName       String          Required (e.g. "React", "Docker")
├── imgUrl          String          Required — path to badge image
├── description     String          Optional
│
├── category        Object
│   ├── categoryId  ObjectId        Ref → badgecategories._id
│   └── name        String          Required (e.g. "Web", "DevOps")
│
├── criteria        Object
│   ├── questionNum Number          Required — total questions in the test
│   ├── timeLimit   String          Required — e.g. "15:00" (mm:ss)
│   └── passingScore Number         Required — minimum correct answers to pass
│
└── test            Object
    └── questions   Array<Object>
        └── [...]
            ├── _id           ObjectId    Auto-generated (subdocument)
            ├── question      String      Required
            ├── answers       String[]    Array of choice strings
            └── correctAnswer String      Required
```

### Notes
- The `category` object embeds both `categoryId` and `name` to avoid extra lookups at query time.
- `test.questions` stores the full question bank including the correct answer — this is server-side only; the correct answers should not be returned to the client during an active test.

### API routes that use this collection

| Method | Route | Operation |
|---|---|---|
| `GET` | `/api/badges` | `Badge.find({}).lean()` — returns all badges |
| `GET` | `/api/badges/[id]` | `Badge.findById(id)` — returns a single badge with test |
| `GET` | `/` (Landing page) | `Badge.find({}).lean()` — used to display badges on landing |

## Collection: `badgecategories`

Lookup table for badge categories.

```
badgecategories
├── _id     ObjectId    Auto-generated
└── name    String      Required (e.g. "Web", "DevOps", "Programming Languages", "Databases", "Data Science")
```

### Notes
- Referenced by `badges.category.categoryId`.
- Not directly queried by any API route — used as a reference for seeding the `badges` collection.

## Collection: `otps`

Stores active OTP codes for email verification. Documents auto-expire after 5 minutes via MongoDB TTL index.

```
otps
├── _id         ObjectId    Auto-generated
├── email       String      Required
├── otp_code    String      Required — 6-digit numeric string
├── isUsed      Boolean     Default: false
└── createdAt   Date        Default: Date.now — TTL index expires doc after 300s (5 min)
```

### Notes
- TTL is set directly on `createdAt` with `expires: 300` in the Mongoose schema.
- A new OTP cannot be requested within 60 seconds of the previous one (rate-limit check in the route).
- After a successful OTP verification, `isUsed` is set to `true` so the code cannot be reused even within the 5-minute window.

### API routes that use this collection

| Method | Route | Operation |
|---|---|---|
| `POST` | `/api/auth/otp` | `findOne({ email })` → rate-limit check → `deleteOne` old → `Otp.create(...)` → send email |
| `POST` | `/api/auth/otp/verify` | `findOne({ email })` → validate code → `findOneAndUpdate({ isUsed: true })` |

## Relationships Diagram

```
badgecategories
    │
    │  category.categoryId (embedded ref)
    ▼
badges
    │
    │  badges[].badgeId (ref)
    ▼
users
    └── badges[]        ← earned badge copies (denormalized snapshot)
    └── experience[]    ← embedded array
    └── education       ← embedded object
    └── contact         ← embedded object

pendinusers             ← temporary, deleted after User is created
otps                    ← temporary, TTL auto-delete after 5 min
```

## Registration Flow (how collections connect)

```
1. User fills sign-up form
        │
        ▼
   POST /api/auth/register/pending-users
        → Creates PendingUser (hashed password stored)
        │
        ▼
   POST /api/auth/otp
        → Creates Otp (6-digit code, TTL 5 min)
        → Sends code to email via Nodemailer
        │
        ▼
   POST /api/auth/otp/verify
        → Validates code, marks Otp.isUsed = true
        │
        ▼
   POST /api/auth/register
        → Reads PendingUser → creates real User
        → Deletes PendingUser
        → Returns JWT token
```
